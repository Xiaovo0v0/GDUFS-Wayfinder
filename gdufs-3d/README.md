# 尚行 · 双校区 3D 地图

本目录是当前校园导航页面的源码。大学城校区数据结合 OpenStreetMap 与已整理的校园资料；白云山校区主要来自校方平面图矢量化，并参考 OSM 路网配准。地图几何和路网是示意数据，使用时请以现场为准。

## 运行

在仓库根目录运行 `python -m http.server 8080 --directory gdufs-3d`，打开 [http://127.0.0.1:8080/](http://127.0.0.1:8080/)。Windows 也可使用根目录的 `start.cmd` 或 `serve.ps1`。Three.js 等依赖位于 `vendor/`，无需 npm 或 CDN；浏览器需要支持 WebGL。建议使用 HTTP 服务访问。

| 地址参数 | 作用 |
| --- | --- |
| `?campus=north` | 白云山校区；默认大学城校区 |
| `?lang=en` | 英文界面 |
| `?ai=off` | 强制本地规则问答 |
| `?ll=23.06829,113.3946,15` | 模拟定位：纬度、经度和精度米数 |

## 使用

- 搜索地点或选择快捷分类；点击建筑也可打开地点详情。选择「到这里」并填写起点后查看路线，再选择「出发」进入漫游。
- 地图支持拖动、缩放、2D/3D、重置、定位和图层控制；地名可统一显示或隐藏。
- 顶部太阳 / 月亮按钮切换日间与夜间色系，选择保存在浏览器本地。
- 地点卡中的「到这里，可以办什么？」按地点显示办事事项；「语心」提供问答、路线意图、Dify 重连和本地降级。

## 当前数据规模与限制

大学城数据包含 51 个建筑条目、101 条道路、147 个路网节点和 156 条边；白云山数据包含 42 个建筑条目、92 条道路、145 个路网节点和 180 条边。两校区分别计算路线。道路未覆盖的小径和建筑接驳可能影响结果，地图不保证测绘精度。

以下章节保留旧版数据整理、建模及精度记录；其中视觉细节和历史文件路径不一定代表当前页面。

## 历史数据来源与建模方法

数据来自 `gdufs-south-campus/04_gis/`：

1. `buildings.geojson` — 建筑体块**真实轮廓多边形**（EPSG:4326），拆分连体后为 51 栋
2. `roads.geojson` — 85 条校园及周边道路（后续重建补入步道与内部路径，模型里现为 101 条）
3. `landscape.geojson` — 水系、绿地、运动场
4. `campus_boundary.geojson` — 校园边界
5. `pois.geojson` — 校门 / 入口

转换脚本 `gdufs-south-campus/scripts/build_nav_data.py`：

- 用 pyproj 把 EPSG:4326 投影到 **EPSG:32649（UTM 49N）**，再减去模型原点
  （E 745081.015, N 2552892.658），得到局部米制坐标；
- **沿 x 轴镜像**：使正北朝上时东在右侧（与常规地图、官方标注图一致）；
- **拆分连体体块**：源数据中「实验楼A–E区」「教学楼E/F/G栋」各是一个连体多边形，
  脚本按主轴垂直切口拆成单栋；
- 多边形用 shapely 简化到 0.4 m 容差，闭合环校验通过；
- 输出 `gdufs-data.js`（约 86 KB）。

**名称/层数/高度修正**：以 `data/official/` 的官方档案为准，逐条记录在 `info-data.js` 的 `source` 字段。依据见
`../docs/02-三维模型修正与视觉升级.md` 与 `../data/official/`。

## 寻路原理（沿道路网络 + 隧道唯一跨路）

1. 从 `roads.geojson` 构建**道路拓扑图**：裁剪到校园范围外扩 45 m，
   用 `unary_union + linemerge` 在交叉口打断并合并成路段，端点 2.5 m 内合并为同一节点；
2. **南北唯一通道**：取南北两块校区范围各外扩 45 m 的重叠走廊作为「地面屏障」，
   所有地面道路在该走廊内被切断，只保留 OSM 中 `tunnel=yes` 的地下隧道及其步行引道；
3. 每个建筑 / 校门：取**最近的道路点**，在该处切开路段建立接入节点，
   再从道路点接一段到建筑外轮廓（门/接驳段），保证所有地点都接入主路网；
4. 用 **Dijkstra** 在道路图上求最短路径（注释写作 A*，实为 Dijkstra），路径严格沿路段折线绘制；
5. 距离 = 沿道路长度（含接入接驳段）；明显转角用黄色圆点标出；
6. 路线经过隧道时，状态栏会标注「经地下隧道穿行」，隧道在图中以青色半透明带 + 两端入口环表示。

当前图规模：南校区 147 个节点 / 156 条边 / 50 个可选地点（44 栋命名建筑 + 6 个已定名校门）；
北校区 145 个节点 / 180 条边 / 37 个地点（34 栋命名建筑 + 3 个校门，走同一套算法，两校区数据各自独立）。

### 校门（按官方平面图命名）

官方迎新网平面图（<https://yx.gdufs.edu.cn/n.jpg>）只标注 **6 个出入口**；官方从未使用"东门/南门/西门/东北门/西北门"。

| 官方名 | 位置 | 坐标 (x=西正, z=北正) | 依据 |
|---|---|---|---|
| 正门 | 东北角，外环东路 | (−251, 192) | OSM 门位 |
| 行政出入口 | 东南侧，外环东路 | (−375, −220) | OSM 门位 |
| 1号门 | 中部，中环路（文采园与隧道之间） | (−7, −170) | OSM 门位 |
| 2号门 | 外环东路南段，友苑南侧 | (−25, −576) | 道路×边界交点（推算） |
| 3号门 | 西侧，外环西路（学生活动中心旁） | (197, −474) | OSM 门位 |
| 4号门 | 西南角，内环东路（风采园旁） | (284, −706) | 道路×边界交点（推算） |

> 2/4 号门是推算值（`name_confidence: "inferred"`），现场核对后改 `x/z` 即可。
> 旧版"北门""西北门""西南门""生活区4号门"等称谓是按方位自拟的，已废弃。
> 数据里另有 3 个未命名出入口（`entrance: emergency/exit`），只画门柱、不进下拉框。

### 水系

- 河道/水渠：来自 OpenStreetMap（`waterway=river/canal`），9 条线、63 个点，渲染成 7–11 m 宽水带。
- **语心湖**：OSM `relation/19177031`（`water=lake`，184 个顶点），另含体育场东侧湖面（`relation/19159564`）。
- 树木生成时会避开水面（1 008 → 975 棵）。

**连通性验证**：移除隧道区域后，南北校区 36 组起终点组合全部不可达；保留隧道后 9 组全部可达。
即隧道是南北之间唯一的地面通道。

## 两校区地理配准（2026-11-01）

| | 南校区（大学城） | 北校区（白云山） |
|---|---|---|
| 原点 WGS84 | `23.066554348076398, 113.39215489681557` | `23.20385672, 113.28631562` |
| 换算 GCJ-02 | `23.06403205, 113.39767419` | `23.20122880, 113.29167352` |
| 范围（WGS） | 113.389119–113.396715 / 23.059307–23.073777 | 113.281878–113.289232 / 23.200291–23.208122 |
| 尺寸 | 778 × 1600 m | 752 × 866 m |
| 依据 | 既有 UTM / OSM 数据 | 官方平面图矢量化 + OSM 路网 ICP |
| 残差 | 路网 median 0.39 m（强制纯平移 3.14 m） | 路网 median 11.5 m；同名建筑 median 39.1 m |

- 换算公式在 `geo.js`：`lon = lon0 − x / (111320·cos lat0)`，`lat = lat0 + z / 110540`。
- 北校只解平移、不解旋转——`geo.js` 的 `project()` 只做平移，旋转与尺度存不进去；单独试过「只放旋转」的 ICP（θ = −0.67°，median 11.04 m，纯平移 11.48 m），差别可以忽略，说明剩余误差来自平面图概括、不是朝向。
- 两校区相距 18.71 km、方位 144.6°。坐标、方法与复现命令见 [`../docs/GEO-LOCK-2026-11-01.md`](../docs/GEO-LOCK-2026-11-01.md)。

## 精度与已知限制

1. **高度**：图书馆（6 层/25 526 ㎡）、大会堂（2 层/8 375 ㎡）、艺术楼（5 层）、院系办公楼（4 层）、
   学术交流中心（6 层）、体育馆（3 层）按**广州市规划验收合格证**修正；
   其余教学楼/实验楼/行政楼/看台仍为**类型估算**（教学楼 E 栋 5 层为唯一硬证据）。
2. **轮廓为体块级**：「实验楼A–E区」「教学楼E/F/G栋」是连体体块，本模型按主轴等分拆分，
   切口位置为几何等分、非实测分界；**实验楼 A–E 的区号方向已用官方平面图逐栋核对通过**
   （E→D→C→B→A 由北向南）。
3. **寻路依赖 OSM 道路/步行道数据**：OSM 未覆盖的小径、楼间连廊可能缺失，
   个别建筑与道路之间用直线接驳段连接；道路属性（是否可步行、是否台阶）未全部参与判断。
4. **隧道走向来自 OSM**：按 `tunnel=yes` 的步行隧道建模，长度约 70 m、连接生活区与教学区；
   隧道实际入口位置与内部走向请以现场为准。
5. **立面为程序化生成**：窗格密度、色彩按建筑类型与官方照片推定，不是逐栋实测立面。
6. **2/4 号门坐标为推算值**：由道路与校园边界的交点推得，待现场核对。
7. **水系精度**：页面采用现有矢量水系数据，位置和边界仍需结合官方资料及现场核对。
8. **不是测绘成果**：不能用于报建、消防、日照、造价等用途。
9. **北校区残差主要是「平面图本身就是示意图」**：单栋建筑 30~88 m 的偏差不是原点错——官方平面图把第六教学楼画成 8490 ㎡、OSM 实测 6142 ㎡，模型按概括矩形建模，质心自然偏。原点本身由两种独立方法（路网 ICP / 同名建筑最小二乘）收敛到相距 4 m 的同一点。
10. **南校区 0.94° 的旋转没有建模**：`project()` 只做平移，在 800 m 尺度上远端约 ±13 m；要彻底解决得给 `geo.js` 加旋转/尺度字段。
11. **楼名三源不一致**：北校「云山一~十九栋」与「云山学1~17栋」数量都对不上；南校 C16/C18 与平面图上的四块「师苑」也无法用坐标消解。逐栋对照见 [`../docs/BUILDINGS-2026-11-01.md`](../docs/BUILDINGS-2026-11-01.md)。
