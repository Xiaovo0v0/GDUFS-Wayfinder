## 二、逐项修复（`gdufs-3d/app.js`）

### 1. 横道逐顶点越界闸门（`renderCrosswalks` 内，删 8 条坏横道的关键）

老逻辑只检查横道**中点线上**的点是否在沥青上（`onRoadAt`），斜交错位路口的整条横道
（17/17 顶点在草上，压深 4.02 m）也能过关。加了：

```js
// 8 个采样点：垫层四角 + 中轴两点 + 白条外沿两点，取最大压出深度
var worst = 0;  [...].forEach(function (pp) {
  var d = roadOverhang(ox, oz);        // 该点到最近车行道中心线的距离 − 半宽
  if (inAnyRing(ox, oz)) d = -1;       // 路口盘内算沥青
  if (d > worst) worst = d;
});
if (worst > 0.15) return;              // 允许 0.15 m 贴边（圆角+量测噪声）
```

新函数 `roadOverhang(x,z)` 返回「压出路面外沿多深」而非布尔值——0.1 m 的贴边可容忍，
4 m 的整块漂草必须杀。阈值 0.15 m 是看图定的：软件渲染 + 路缘圆角下的 1 px 级过渡不该触发重画。

### 2. 盘间空隙盖面（`renderCrosswalks` 盖面段）

- 老做法「盘心凸包外扩 5.5 m」只盖住了 16/36。改成**整组 rings 真凸包向心内缩 0.35 m**，
  35/36 一次盖齐；凸包 ⊆ 沥青并集，天然不会压草。
- 凸包顶点过滤：离所有盘心都超过「该盘 ring 最大离心距 + 1.6 m」的顶点（四条腿之间的
  草地尖角）不参与铺面。
- **分组来源扩了**：原来只把「4 臂盘」并组，T 口（2 臂）/6 臂盘和「盘心距 16~34 m 但臂
  端距 <18 m 的双幅主路拆盘」都不入组（漏了 20 处）。现在用 `allJ`（全部有 rings 的盘）
  分组 → `groups`（4 臂盘，画横道用）+ `groupExtra`（非 4 臂盘，只为盖面）。臂向链接规则：
  两盘臂向差 <8°（含反向）且臂端距 <18 m → 同一组。
- 注意**没有**采用「组臂轴交点距离 >13 m 就整组不画横道」的斜交判定：双幅×双幅的四个盘
  在彼此轴线上交点距离天然超过盘径，和真斜交在数值上不可分（试过，bands 66→3，全灭）。
  真正可靠的是上面的逐顶点闸门。

### 3. 转角圆弧（新 IIFE `renderJunctionCorners`，路口圆角的存在感主要来自它）

原理：按每对相邻开臂 A/B，求「A 的 B 侧路缘线」与「B 的 A 侧路缘线」的交点 P；半径
R = 0.7×min(半宽)，切线长 R/tan(φ/2) 定切点 T1/T2，圆心 C = P + 角平分线方向 × R/sin(φ/2)；
P→T1→七段弧→T2 的扇面铺人行道贴图（y=0.6047，polygonOffset -19），沿弧外侧 0.45 m
压一圈深色路缘带（y=0.6053，-20），盖在路口补面（-16）之上、白条（-24）之下。

- 闸门：相邻臂夹角 50°~150°、两臂均 open、从 P 出发的两条边线射线 0.2 m 落点必须
  `onOtherRoad` 命中沥青（双幅内臂指向中央分隔带草地，自动剔掉）。
- 计数：南 132 组 / 924 三角；北 26 / 182。北校少是因为北校道路窄、路口小，圈不出短切线。
- 产出 mesh：`roadGroup.userData.cornerFillets`（转角个数）。

### 4. 步道带 z-fighting（`roadSidewalk` / 步行道分支）

两条相交主路的步道带在路口象限**完全共面**（y=0.57 同材质同 polygonOffset）→ 软件光栅下
逐像素闪烁。每条路给 `(ri % 9) * 0.0011` m 的高差，肉眼不可见（1 mm 级），深度缓冲稳了。

### 5. 「道路不连续」的定性结论（没改数据，全部有依据）

- 31 个 `orphan_ends` 里：双幅主路并行两幅之间的自然间隔（内环 19/20、84/92、中环 16/97，
  延长线平行错距 0.00 m）+ 校门口/数据边界截断（外环 50/93/95 朝校区外）+ <2 m 近缝由
  `ribbonGeometry` 的方头 cap（延长 w/2）天然盖住 + service 园区路端点本就互通到 footway。
- **没有真断缝**。「看起来断」的地方是双幅路两幅的中间间隔，这在真实校园里就是绿的
  中央分隔带，不是 bug。

## 三、踩过的坑（重要的在前）

1. **组斜交判定不可用**：`bandIsSkewed` 想靠「组内臂轴交点离盘心距离」筛掉斜交组，结果
   双幅×双幅正常路口也中枪（66→3 条），因为拆盘后臂轴与邻盘的交点天然远。删之，
   交给逐顶点闸门——它看的是「这条横道到底在不在沥青上」，通用且无假阳性。
2. **采样距判定盖面是假阴性**：0.4 m 步长的采样「没打到三角形」≠ 没盖住。改用精确
   point-in-triangle 后 16/36 → 35/36。验收器自己也要对齐到精确算法。
3. **north-data.js 不能用贪婪正则取 JSON**：文件尾还有别的语句，`json.loads(re.search(...))` 炸
   `Extra data`。用 `json.JSONDecoder().raw_decode` 取第一个对象。
4. **鲁棒的北校分组**：北校主路宽 13 m 的盘，16 m 的 GROUP_R 圈不到它身边 16.6 m 处的
   同一拆盘成员；臂向链接规则（8° / 18 m）是为此设计的，南校双幅路口同样受益。
5. **cwtest.mjs 提取范围扩大**后需要补 `walkTex`（现在全空的 `{}` 即可，材质只用到它当真值）。
6. 视觉验收机位要给到位：`window.__navDebug.camera.position.set(x,y,z)` + `controls.target.set(...)`
   + `controls.update()`，`--nohud --compose --wait 4500`。远全景看不出这轮的修复效果，必须近机位。
