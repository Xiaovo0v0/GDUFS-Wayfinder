## 一、这轮做了什么

### 1. Dify 平台能力探查（已完成）

- 用无头浏览器（Edge + CDP，等效"computer use"）登录 `http://172.17.1.46` 实操，配合控制台 API 抓包核对。
- **平台为 Dify 1.17.1 社区版**；模型：DeepSeek-V4-Flash-0731（对话）、bge-m3（向量）、bge-reranker-v2-m3（重排）。
- 确认的能力：5 种应用形态、18 类工作流节点、知识库三档分段 + 混合检索 + 重排、MCP / Swagger API / 工作流作为工具三类工具接入、WebApp / iframe / Service API / MCP 四种发布方式、Agents(BETA) 与 Skills（SKILL.md 规范）。
- 详细报告：[`01-Dify平台能力探查报告.md`](01-Dify平台能力探查报告.md)；证据截图与接口原始返回在 `../artifacts/dify/`。

**结论**：Dify 不做地图/3D，它是"大脑"；我们的 Three.js 校园地图是"眼睛"。推荐 **方案 C：自定义前端 + Dify Service API**，Dify 输出结构化动作 JSON，前端执行飞行定位/画线/弹卡片。

## 二、已拍板的三个决定（2026-10-18）

| 问题 | 决定 |
|---|---|
| 作品形态 | **方案 C：自定义前端 + Dify Service API**（3D 为主界面，Dify 只返回结构化动作 JSON） |
| 公开访问 | **公网静态页 + 前端离线兜底**（3D 页托管公网，本地算路 + 本地 FAQ 保底；Dify 在线时增强） |
| 下一轮优先级 | ① 建 Dify 知识库 + Chatflow 主应用 ② 3D 页对接 Dify API ③ 补 3D 精度（2/4 号门、实验楼 A–E、语心湖） |

### 执行计划（按顺序）

1. **知识库**：`广外办事指南`（Q&A 分段，40 条语料）+ `广外校园百科`（建筑/场馆/食堂 58 条）。加 `department` / `campus` / `building` 元数据。
2. **Chatflow 主应用**「广外校园向导」：
   `开始 → 问题分类器（导航/办事/百科/闲聊）→ 导航支：参数提取器(from/to) → 路线工具 → 输出 JSON；办事支：知识检索 → LLM 组织答案 + 卡片字段；百科支：知识检索 → LLM`
3. **路线工具**：优先用「代码执行」节点内置 220 节点路网（离线可跑），再补 Swagger API 版本。
4. **前端对接**：`app.js` 增加 `askDify(text)`，解析 `{intent, from, to, route, answer, card}`，驱动相机飞行 / 画线 / 侧栏卡片；网络失败时回落到本地规则引擎。
5. **3D 精度**：用官方 8787×8787 平面图做控制点配准 → 定位 2 号门 / 4 号门；核对实验楼 A–E 的区号方向；补语心湖水面与河道。

## 五、风险提醒

1. **Dify 账号是团队共用**：目前工作区只有 1 个成员、8 个测试应用，建议尽快建正式应用并打标签区分。
2. **插件市场可用但未装任何插件**：MCP 能力需要先装 `MCP server` 扩展才能对外暴露。
3. **模型是 DeepSeek-V4-Flash**：做参数提取/分类够用，长文生成偏弱，答案尽量走模板。
4. **评委可能打不开内网链接**：见 Q2，务必提前准备公网方案。
5. **GLB 只能在 http 下加载**：`file://` 会回落程序化几何；公网部署不受影响。
