# 广外两校区建筑名录（2026-11-01）

配套文档：`docs/GEO-LOCK-2026-11-01.md`（那份讲「校区钉在经纬度哪里」，这份讲「每栋楼叫什么」）。
机器可读版：`artifacts/lock/names_north.csv`、`names_south.csv`（UTF-8 BOM，Excel 直接开）；
同一份内容的 Markdown 全表：`artifacts/lock/names.md`。

## 一句话

模型里北校 42 栋、南校 51 栋，名字来自校方平面图；叠上 OSM 后北校到 159 条命名要素、
南校到 94 条。剩下的 13 栋（北 6 / 南 7）平面图本来就没写名字，OSM 也没有，
`第五教学楼`、`云山学3栋` 两栋是拿 OSM 邻近建筑反推的，标了待核。

**那个网址（`map.jiqrxx.com/map/5051.html`）本身给不了名字** —— 它只是把注记画进瓦片像素里。
下面是「为什么拿不到」和「绕过去之后拿到了什么」。

## 为什么不能直接从地图接口取名字

| 接口 | 返回 | 结论 |
| --- | --- | --- |
| 腾讯 `rt0.map.gtimg.com/tile?z&x&y&styleid=3` | 6723 B 的**贴图 PNG**（注记是像素），`y` 要按 TMS 取 | 能看，不能解析 |
| 腾讯 `realtimerender?type=vector&style=0` | JPEG 栅格 | 不是 MVT protobuf |
| 腾讯 `apis.map.qq.com/ws/place/v1/search` | `{"status":311,"message":"key格式错误"}` | 要有效 key |
| 高德 `www.amap.com/service/poiInfo` | 84 KB 反爬 HTML（阿里 punish 页） | 直接拒 |
| 天地图 `vec_w/cva_w` | tk 失效时 418 | 要注册 |
| 本机 OCR | tesseract / pytesseract / easyocr / paddleocr / rapidocr 全无 | 无兜底 |

所以这三条路都不通：API（要 key）、矢量瓦片（是图片）、机读 OCR（没装）。
可行的是 OSM（ODbL，有结构化 `name`）+ 模型自带的平面图名 + 人眼读高德注记。

## 三套命名对着看

| 对象 | 模型（校方平面图） | 高德 | OSM |

| 北校西南教工宿舍 | 未建模 | 教工宿舍26栋、68栋… | 只写编号「26栋」「68栋」 |
| 南校宿舍 | 南苑N栋 / 北苑N栋 / 师苑N栋 | 只有「7栋」「10栋」这类编号 | 1栋、2栋、3栋 |

最后一行是实打实的冲突：OSM 那条 `building=yes` + 名字后缀写着已拆除，高德 z18 还把
「云山学3栋」画在宿舍群里。模型 N037 反推到的正是这个名字，所以标了待核 —— 现场或
校方平面图才能定案。

## 名字对不上的三种情况（能不能自动消解）

用 `tools/lock/merge_names.py` 把三套名字对撞了一遍（互为最近邻 + 20 m 上限才认作同一栋，
放宽到 60 m 会大面积串名）：结果在 `artifacts/lock/names_canonical.json`、
冲突清单 `artifacts/lock/names_conflicts.md`。93 栋建模楼里 **46 栋拿到了别的来源的别名**，
剩下的对不上，分四类。

| 类型 | 例子 | 能不能自动消解 |
| --- | --- | --- |
| 写法差异 | 云山三栋 / 云山学3栋 / 3栋；南苑7栋 / 7栋；教工宿舍26栋 / 26栋 | 能，规则归一 |
| 同义异名 | 行政楼 ↔ 行政办公楼；门诊部 ↔ 校医院；B004 行政办公楼 ↔ 校办公楼 | 基本能，同位置 + 词干 |
| 编号错位 | 模型「云山十三栋」位置上 OSM 叫「云山学14栋」；模型「云山三栋」位置上挂着「云山学3栋（已爆破拆除）」 | **不能**。配准残差中位数 39 m，宿舍排间距约 50 m，两者同量级，谁是谁排不出来 |
| 一号多楼 | 「3栋」＝北校云山三栋＝南校北苑3栋＝南校师苑3栋；「17栋」在三个位置各有一个 | 只能靠**校区范围**，全局唯一化不可能 |

重名 19 组、真异名 6 组（其余是写法或同义）。具体：

- `3栋` / `1栋` / `2栋` / `7栋` / `11栋` / `17栋` 这类纯编号，两校区都有人用，北校还有
  「云山N栋」和「教工宿舍NN栋」两套编号并行。
- `N020 云山十三栋` ↔ OSM `云山学14栋`，`N031 云山三栋` ↔ OSM `云山学3栋`：模型这套
  「云山一~十九栋」的序号和现场「云山学1~17栋」明显不是同一套，且数量都对不上（19 vs 17）。
- `N027 BBA教育中心` 位置上 OSM 写 `第三食堂`：不是同义，是两栋楼挨太近被互认成最近邻，
  这类在密集区会零星出现，所以别名不能无条件信，只能当「可能叫法」。

## 怎么定这件事

1. **主名 = 校方平面图名**，界面显示永远用主名（现状就是这样，不动）。
2. **别名只给搜索用**，不给显示用；别名命中后要高亮提示「已按别名匹配到 X」。
3. **搜索按当前校区解析**：`3栋` 在北校应该是「云山三栋 / 教工宿舍3栋」，
   在南校才是「北苑3栋 / 南苑3栋」。现在 `app.js:3270` 那段编号补全是**写死南校**的
   （`7~13 → 南苑`、`1~6 → 北苑`），北校搜「3栋」直接落空，需要按 `CAMPUS` 分支。
4. **高德 / OSM 只当参考名录**，不当真值；带编号的名字永远标注来源，别混进主名。

## 复现

```bash
# OSM（要联网，Overpass 会 504，脚本自带 5 个镜像轮询）
node tools/lock/fetch_osm.mjs --bbox 23.190,113.275,23.215,113.300 --out artifacts/lock/osm_north2.json
node tools/lock/fetch_osm.mjs --bbox 23.056,113.380,23.078,113.404 --out artifacts/lock/osm_south.json

# 汇总（模型 + OSM，含坐标换算与 CSV/MD 输出）
python tools/lock/build_names.py

# 三套名字对撞：主名 + 别名 + 冲突清单
python tools/lock/merge_names.py

# 高德注记对照图（--bbox 用 GCJ-02，不是 WGS84）
python tools/lock/tencent.py --layer amap --bbox 113.2866,23.2015,113.2952,23.2062 --z 18 --out artifacts/lock/amap_n1.png
python tools/lock/tencent.py --layer amap --bbox 113.3944,23.0638,113.4022,23.0715 --z 18 --out artifacts/lock/amap_s1.png
```
